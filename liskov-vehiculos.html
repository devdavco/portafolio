SOLID — Principio L

LSP en un sistema de arriendo de vehículos

Ejemplo práctico usando el dominio de una empresa de arriendo de carros, con base de datos y lógica de negocio real.

Tenemos una empresa de arriendo. Cada vehículo tiene una tarifa diaria y puede generar el costo total de un arriendo. El sistema procesa cualquier Vehiculo de manera uniforme — esa es la promesa del contrato base.

🗄️ Contexto — Base de datos

El sistema se apoya en estas tablas. Todo vehículo registrado se asume disponible para arrendar.

vehiculos (id_vehiculo, marca, modelo, anio, placa, tarifa_dia, id_tienda)
clientes (id_cliente, nombre, email, telefono)
alquileres(id_alquiler, id_cliente, id_vehiculo, fecha_inicio, fecha_fin, precio_total)

-- precio_total = tarifa_dia × cantidad de días

❌ Violación — VehiculoEnMantenimiento

VehiculoEnMantenimiento extiende Vehiculo, pero lanza una excepción en calcularCosto() porque no debería arrendarse. El sistema que procesa vehículos no sabe que algunos no pueden arrendarse — y explota en runtime.

Vehiculo.java 
public class Vehiculo {
    protected String placa;
    protected String marca;
    protected double tarifaDia;

    public Vehiculo(String placa, String marca, double tarifaDia) {
        this.placa     = placa;
        this.marca     = marca;
        this.tarifaDia = tarifaDia;
    }

    public double calcularCosto(int dias) {
        return tarifaDia * dias;
    }

    public String generarResumen(int dias) {
        return "Arriendo de " + marca +
               " | Días: " + dias +
               " | Total: $" + calcularCosto(dias);
    }
}
VehiculoEnMantenimiento.java Viola LSP 
public class VehiculoEnMantenimiento extends Vehiculo {

    public VehiculoEnMantenimiento(String placa, String marca) {
        super(placa, marca, 0);
    }

    @Override
    public double calcularCosto(int dias) {
        // ❌ rompe el contrato — cualquier Vehiculo debería poder calcular
        throw new UnsupportedOperationException(
            "Este vehículo está en mantenimiento y no puede arrendarse"
        );
    }
}
SistemaArriendo.java Explota en runtime 
public class SistemaArriendo {

    // espera cualquier Vehiculo y asume que puede calcular costo
    public static void procesarArriendo(Vehiculo v, int dias) {
        System.out.println(v.generarResumen(dias)); // 💥 si v es VehiculoEnMantenimiento
    }

    public static void main(String[] args) {
        Vehiculo toyota = new Vehiculo("ABC123", "Toyota", 85000);
        Vehiculo dañado = new VehiculoEnMantenimiento("XYZ999", "Ford");

        procesarArriendo(toyota, 5);  // ✅ "Arriendo de Toyota | Días: 5 | Total: $425000"
        procesarArriendo(dañado, 5);  // ❌ UnsupportedOperationException
    }
}

El problema

SistemaArriendo confía en que todo Vehiculo puede arrendarse. VehiculoEnMantenimiento rompe esa promesa silenciosamente — el error aparece solo cuando el programa ya está corriendo.

✅ Solución — Interfaz Arrendable

Solo los vehículos disponibles implementan Arrendable. VehiculoEnMantenimiento sigue siendo un Vehiculo en el sistema (existe en la BD), pero nunca promete que puede arrendarse. El sistema ahora solo acepta Arrendable — el compilador bloquea el error antes de que ocurra.

Vehiculo.java 
public class Vehiculo {
    protected String placa;
    protected String marca;

    public Vehiculo(String placa, String marca) {
        this.placa = placa;
        this.marca = marca;
    }

    // solo datos comunes — sin prometer que puede arrendarse
    public String getPlaca() { return placa; }
    public String getMarca() { return marca; }
}
Arrendable.java 
public interface Arrendable {
    double calcularCosto(int dias);
    String generarResumen(int dias);
}
VehiculoDisponible.java 
public class VehiculoDisponible extends Vehiculo implements Arrendable {
    private double tarifaDia;

    public VehiculoDisponible(String placa, String marca, double tarifaDia) {
        super(placa, marca);
        this.tarifaDia = tarifaDia;
    }

    @Override
    public double calcularCosto(int dias) {
        return tarifaDia * dias;
    }

    @Override
    public String generarResumen(int dias) {
        return "Arriendo de " + marca +
               " | Días: " + dias +
               " | Total: $" + calcularCosto(dias);
    }
}
VehiculoEnMantenimiento.java 
public class VehiculoEnMantenimiento extends Vehiculo {
    // no implementa Arrendable — no promete lo que no puede cumplir ✅
    public VehiculoEnMantenimiento(String placa, String marca) {
        super(placa, marca);
    }
}
SistemaArriendo.java Correcto 
public class SistemaArriendo {

    // ahora exige Arrendable — no acepta vehículos en mantenimiento
    public static void procesarArriendo(Arrendable v, int dias) {
        System.out.println(v.generarResumen(dias));
    }

    public static void main(String[] args) {
        VehiculoDisponible      toyota = new VehiculoDisponible("ABC123", "Toyota", 85000);
        VehiculoEnMantenimiento ford   = new VehiculoEnMantenimiento("XYZ999", "Ford");

        procesarArriendo(toyota, 5); // ✅ "Arriendo de Toyota | Días: 5 | Total: $425000"
        procesarArriendo(ford,   5); // ❌ error de compilación — Ford no es Arrendable
    }
}

La solución

El compilador bloquea el error antes de correr el programa. VehiculoEnMantenimiento sigue existiendo en el sistema (y en la BD), pero nunca puede pasarse donde se espera un Arrendable.
